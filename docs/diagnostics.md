# 排障工作台与证据包复盘指南

启动 Web 服务后访问 `/diagnostics`（桌面版默认直接进入工作台）。工作台与对应 API 仅接受本机连接，同一数据目录由单个服务实例使用。

## 1. 支持协议与原始产物

采样支持 1–300 秒（默认 60 秒）。单次原始产物上限由 `server.max_dump_mb` 配置，默认 128 MiB，可调范围为 1–128 MiB；该上限与可移植证据包校验上限一致，不支持 `0` 或超过 128 MiB。达到上限、手动停止或读流失败时会保留已采集的数据与可用报告，报告中的 `manifest.stream_limit_bytes`、`manifest.stream.bytes` 和 `observation.end_reason` 分别记录本次上限、实际保存字节与结束原因。

| 协议 | 原始产物 | 说明 |
| --- | --- | --- |
| **HTTP-FLV** | `stream.flv` | 采样期间读取的完整 HTTP 响应体，报告可定位媒体帧 PTS/DTS 及原始字节范围 |
| **RTMP / RTMPS** | `stream.rtmp` | 从服务端握手开始的原始接收字节；RTMPS 保存 TLS 解密后的 RTMP 协议数据 |
| **RTSP / RTSPS** | `stream.rtsp.zip` | 含服务端应用字节 `server-wire.bin`、DESCRIBE SDP 原文 `session.sdp` 及 `session.json`；UDP 模式另含完整数据报 `udp-datagrams.bin` 及边界/到达/来源索引 `udp-index.ndjson` |
| **HLS** | `stream.hls.zip` | 原始 m3u8 快照、初始化段和 MPEG-TS / fMP4 / 独立音频分片 |
| **HTTP MPEG-TS** | `stream.ts` | 采样期间读取的原始 HTTP/HTTPS 响应体 |
| **UDP MPEG-TS** | `stream.udp` | 按接收顺序拼接的完整 UDP 载荷，时间线记录每个数据报边界 |
| **RTP MPEG-TS** | `stream.rtp` | 保留 RTP 头部与载荷的完整数据报（检查静态载荷类型 PT 33），时间线记录数据报边界 |

- **UDP / RTP 接收地址**：使用 IPv4 接收地址（如 `udp://0.0.0.0:5000` 或 `rtp://127.0.0.1:5000`）；组播可附加 `?interface=en0` 指定本机网卡（省略时由系统选择）。
- **HLS 采样策略**：主清单自动选择带宽最高的常规变体及默认独立音频 rendition；直播从清单末尾最多 3 个完整分片开始并持续跟踪新分片，点播按顺序下载；加密分片保存原始密文。

## 2. RTSP / RTSPS 采样与本机预览

- 摄像头和 NVR 可直接填写带 URL 用户信息认证的 RTSP/RTSPS 地址。RTSP 默认使用 **TCP 交织**，也可显式选择 **UDP 单播 RTP/RTCP**（不会在 UDP 失败时自动回退 TCP）；RTSPS 使用校验证书的 TLS/TCP。
- 报告展示 DESCRIBE / SETUP / PLAY 控制耗时、DNS/TCP/TLS 阶段、SDP 声明轨道与实际 RTP 接收统计；UDP 额外统计符合来源、被过滤及超缓冲的数据报数量。
- **同次采样本机转封装预览**（勾选播放器分析后生效，不另建 RTSP 连接）：
  - **原码转封装**：支持 H.264（packetization-mode 0/1）、H.265（RFC 7798，通过 Enhanced FLV，需浏览器和系统具备 HEVC 解码能力）、RFC 3640 AAC-LC、Opus（48 kHz 单/双声道，保留 2.5–120 ms 实际时长与 DTX 空洞，浏览器按 MSE 能力选 MP4 或 WebM 容器）。
  - **G.711 转码预览**：当无原码 AAC/Opus 轨道时，G.711 PCMA/PCMU 在本机解码并经 FFmpeg 转为 48 kHz AAC-LC 预览，报告单独记录输入/输出样本、缺口补静音、预延迟与本地耗时（不计入网络阶段）。
- **隐私边界**：HTML/JSON 报告与大模型输入仅包含受控方法、状态、编码标签及数字证据，不展示 RTSP 路径、用户信息、认证头或 SDP 原文。

## 3. ONVIF 设备探测

在排障工作台切换至「ONVIF 设备探测」子页，或点击播放地址旁的快捷入口：

- 选择本机 IPv4 网卡发起 WS-Discovery 搜索（1–10 秒），跨 VLAN 或未搜到时可手动填写 Device 服务地址（例如设备的 `/onvif/device_service`）。macOS 需允许应用访问本地网络。
- 支持 WS-Security PasswordDigest、设备 UTC 偏差校正与一次 HTTP Digest 重试。凭据仅用于当前请求，不落盘；默认不将凭据复制到 RTSP 地址，勾选复用后也仅允许同主机。
- 读取媒体 Profile 并选择 TCP/UDP 后点击「使用此流地址」，自动回填采样表单供核对。

## 4. 连接时序、传输指标与脱敏头字段

- **连接时序**：逐跳记录 HTTP 请求与跳转（如 `302 → 200`）、单次耗时、TTFB 以及 DNS/TCP/TLS/发送请求/等待首字节/接收响应头各阶段耗时；RTMP 单独记录握手、应用连接、创建流与播放协商阶段。
- **HTTP 请求与响应头**：HTTP-FLV、HTTP MPEG-TS 与 HLS 每次请求可展开查看脱敏后的请求/响应头（保留重复值）。落盘前对 Authorization、Cookie、Set-Cookie、API Key、Token 脱敏，并移除 URL 头字段的查询参数与用户信息；每组上限 32 字段 / 2 KiB（单值 512 字节）。大模型不接收头字段原文。
- **自定义访问条件**：HTTP-FLV、HTTP MPEG-TS 与 HLS 可为单次采样设置最多 16 个请求头、HTTP/HTTPS 代理和附加 PEM CA 证书。HLS 独立采样与实际播放器代理使用相同配置；CA 与系统证书共同校验，不提供跳过证书校验。请求头值、代理凭据和 CA 内容不写入任务记录，敏感头字段进入报告前仍按上述规则脱敏。
- **传输层指标**：MPEG-TS 展示包长度、PID/编码、PAT/PMT、TEI、连续计数、重复包、同步丢失与 PCR/PES 时间戳检查；RTP 补充序列缺口、重复与乱序统计。

## 5. 播放器体验分析（v1–v4）

勾选「同时分析播放器体验」后，工作台同步播放并记录以下观测维度，所有原始事件写入 `player.json`（SHA-256 校验，支持离线重算）：

- **首屏与缓冲卡顿**：首屏从提交采样计时（优先使用视频呈帧回调），缓冲曲线与卡顿区间对齐后端采样时间轴。首次开始播放后持续 waiting ≥ 500 ms 计为一次卡顿，排除启动、手动暂停、跳转、页面隐藏与正常结束阶段。
- **视频呈帧与丢帧（v2）**：优先使用 `getVideoPlaybackQuality`（兼容 WebKit），记录连续前台播放的帧增量、丢帧率、计数重置与最大呈帧回调间隔。
- **页面调度观测（v3）**：记录浏览器长任务（≥ 50 ms，需 Long Tasks API 支持）与 250 ms 采样定时器延后（≥ 100 ms），仅用于辅助排查主线程调度，不增加卡顿次数。
- **呈帧回调间隔（v4）**：建立基线后记录两端均有视频帧回调且间隔达到 `max(1000 ms, 3 × 基线中位数)` 的完整区间，即使无 waiting 也可独立触发证据补查。
- **HLS 实际播放请求代理台账（`player-network.json`）**：HLS 原生与 hls.js 播放均经本地代理，记录最多 512 次匿名化请求及 v2 逐跳阶段耗时（最多 8 跳/请求、16 阶段/跳，总预算 256 KiB），与独立采样连接分开展示。

## 6. 卡顿证据补查、自动汇总与分层排查

### 自动补查与整体汇总

- 勾选播放器体验后默认开启「采样后自动补查并汇总」（也可关闭改为手动）。
- 采样结束并收到完整播放器记录后（最多等待 30 秒），系统按与采样窗口的重合时长自动筛选最多 3 个互不重合的关键缓冲卡顿或呈帧回调间隔，提取媒体片段与截图，完成后发起一次整体汇总。任务状态写入 `automatic-investigation.json`，导入历史证据包时仅复盘快照，不自动续跑。

### 手动补查与媒体提取

- 每份报告最多补查 8 次异常（自动与手动共享上限），自动关联前后 3 秒的收流间隔、缓冲样本、最近关键帧、HTTP/代理请求与页面调度区间并分配独立证据 ID。
- 若本机具备 `ffmpeg` / `ffprobe`，后台仅读取本地原始流（支持 HTTP-FLV/RTMP/HLS/TS 及 RTSP `stream.rtsp.zip` 离线重建），生成最多 15 秒的 H.264/AAC MP4 与异常前、附近、后 3 张 JPEG 截图，派生文件保存在证据包 `stalls/S001/` 等目录。
- **本地分层排查方向**：无需大模型在线即可在本地生成「已观测 / 待验证 / 证据不足」的分层排查结论与下一步检查建议（例如区分源端供给不足、本机播放调度异常或 HLS 实际播放请求慢/失败）。
- **多模态图文输入**：配置模型后，「自动图文」模式会随关联时序发送最多 3 张截图（单张 ≤ 512 KiB，按 SHA-256 去重）；「仅文本」模式仅发送时序与证据 ID。报告明确记录请求设置、实际采用模式、回退原因与截图指纹，离线导入完整校验。

## 7. 证据包导入与本机回放源

- **证据包复盘**：下载的 `evidence.zip` 包含原始流、规则报告、播放器与补查记录及 SHA-256 清单。导入时无需源流、FFmpeg 或大模型在线，本地校验完整性并按采样时间线重新运行规则。
- **本机回放源**：HTTP-FLV 与 RTSP（TCP/UDP）报告支持一键启动「本机回放源」，按证据包记录的原始字节与相对到达间隔向多个客户端回放，便于复现现场接收时序。

## 8. 证据存储与生命周期

- 排障记录侧栏展示记录数、原始产物与派生文件的总占用，以及重要证据的数量和字节数。
- 「保护当前证据」用于保留关键现场；受保护记录不会被单条删除、批量删除或保留策略清理，需先显式取消保护。
- 可删除当前记录，或勾选多条已结束记录批量删除。删除会同时移除 SQLite 索引和对应本地产物，且不可撤销。
- 「按保留策略清理」支持保留天数（1–3650 天）与磁盘预算，从最早的未保护、已结束记录开始删除；两项设为 0 表示对应策略不启用。该操作按需执行，不会在后台自动清理。
